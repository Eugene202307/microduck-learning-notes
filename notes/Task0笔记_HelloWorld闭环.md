# Task 0 学习笔记：MuJoCo 策略控制 HelloWorld（控制闭环入门）

> 材料：`03-Notebook/00_MuJoCo策略控制_HelloWorld.ipynb`；代码：`02-可运行代码/hello-world/walking_sim.py`

## 1. 任务目标
亲手执行并理解完整控制闭环：`速度命令 → 观测 → 策略推理 → 14 维关节目标 → MuJoCo 物理步进 → 下一步观测`，用 `forward()/turn()/stop()` 控制平地行走。入门任务，不含训练。

## 2. 实验配置
| 项 | 值 |
|---|---|
| 策略 | `BEST_alpha_walking.onnx`（HF 自动下载 + SHA 校验；revision `ad9d41a…`，sha256 `e36332…`） |
| 物理 / 控制频率 | 200 Hz（timestep 0.005 s）/ 50 Hz（`CONTROL_DECIMATION=4`，每控制步 4 次 mj_step = 20 ms） |
| 执行器 | 位置执行器，力矩限幅 0.64 Nm（`TORQUE_LIMIT_NM`） |
| 观测 / 动作 | obs[1,61] → action[1,14]；动作经 `action_scale` 叠加默认姿态成位置目标写入 `data.ctrl` |

## 3. 闭环五步（对应 `walking_sim.py`）
1. **组观测（61 维）**：陀螺仪 3 + 重力投影 3 + 关节位置偏差 14 + 关节速度 14 + 上一步动作 14 + 命令 13；
2. **策略推理**：ONNX Runtime（CPU），[1,61] → [1,14]；
3. **动作→关节目标**：`target = default_pose + action_scale × action` 写入 `data.ctrl`——**全程唯一直接碰物理量的入口**；
4. **物理步进**：4 次 `mj_step`；
5. 回到 1，闭环继续。

## 4. 三个关键认知
- **命令写在观测里**：`forward(0.30)` 只改观测第 48:51 的 3 个期望速度。命令是"意图"，策略是把意图翻译成动作的决策者；**只改命令不跑推理，机器人不动**；
- **stop ≠ 关掉策略**：`stop()` 只是命令清零，策略每个控制步照常运行、负责站稳；
- **无 LSTM 时策略的显式记忆** = 观测 34:48 的"上一步动作"14 维；前馈网络本身无记忆。

## 5. 运行记录
2026-10-14 本机跑通：550 控制步 / 11.02 s，settle(50 步, 零命令) → forward(200 步, vx=0.30) → turn_left(150 步, yaw=0.50) → stop(150 步, 零命令)，一段跑完无摔倒；全程最低高度 0.1133 m、最小 upright_cos 0.9966，末态近乎静止（vx≈-0.001 m/s）。产物：`outputs/00_control_helloworld/control_report.json`、`microduck_forward_turn_stop.mp4/.gif`。

## 6. 自己的观察
1. **命令速度 ≠ 实际速度**：命令 0.30 m/s → 实际位移 0.476 m/4 s ≈ 0.12 m/s；命令 0.50 rad/s → 实际转角 0.729 rad/3 s ≈ 0.24 rad/s。原因：位置执行器受 0.64 Nm 力矩上限约束 + 机身惯性，静差与滞后是"策略能力 + 执行器物理"的能力边界，不是 bug；
2. **响应延迟有两层**：决策链约 1 个控制步（20 ms）+ 执行器/机械惯性滞后（主项，几百毫秒量级），所以 turn 后"过一两步才转起来"；
3. **同值命令重复下发无效果**：两次 `forward(0.30)` 是同值覆盖同值，观测不变则行为不变；命令只在改变观测值时起作用，且从下一个控制步生效；
4. 本次 min_height=0.1133 与发布版 0.1129 的微差属同 SHA 模型的浮点非确定性，重跑不逐比特一致，正常现象。
