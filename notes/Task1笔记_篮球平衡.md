# Task 1 学习笔记：MicroDuck 篮球平衡（PPO / ONNX / GPU）

> 材料：`03-Notebook/01_篮球平衡_PPO_ONNX_BPU_MuJoCo.ipynb`；`01-任务资料/01-MicroDuck篮球平衡强化学习/README.md`（§4 观测表 / §5 奖励 / §6 训练入口 / §7 复核结果 / §9 真机边界）

## 1. 实验逻辑（六步）
① 问题：让鸭子站在自由滚动的篮球上，按速度指令边走边保持平衡 → ② 00 的 walking 模型不可迁移（它假设脚下固定平面，动作节奏会把自由球越推越偏；且球滚动与身体姿态间有隐藏时序关系，单帧前馈判断不了）→ ③ 方案：**换场景不换接口**（沿用 61 维观测约定/14 关节/50 Hz/动作缩放）、**换 LSTM blind actor**（球状态不进观测，靠本体感觉+隐状态推断球的运动）、**PPO + privileged critic 重训** → ④ 执行：复现公开 checkpoint b11（模型契约检查 → ONNX 导出与 parity → GPU 闭环 → 多环境评测）→ ⑤ 结论：链路本地走通 → ⑥ 边界：**这是公开模型的本地复核，不是自训成果；仿真通过 ≠ 真机可用**。

## 2. 观测、动作与 LSTM
- 61 维观测与 00 完全一致：0:3 陀螺 / 3:6 重力投影 / 6:20 关节位置 / 20:34 关节速度 / 34:48 上一步动作 / 48:51 速度指令 / 51:61 零填充；动作 14 维；
- 网络：LSTM(256) → ELU MLP(512→256→128) → 14 维动作；
- ONNX 契约：`obs[1,61] + h_in[1,1,256] + c_in[1,1,256] → actions[1,14] + h_out + c_out`，50 Hz，每步把 h_out/c_out 传回下一步。

**必记易错点**
- **blind ≠ 没记忆**：球的位置/速度不在 obs 里，LSTM 充当"观测器"，从陀螺仪+重力投影+关节感觉随时间推断球的运动（类似卡尔曼滤波）；泛化靠训练多样性（`--push-interval-s 1.5 3` 随机推击、hold 课程）而非部署加传感器；
- **h/c 清零时机**：首次启动 / 摔倒恢复 / 策略切换 / episode reset 时清零；**改速度命令绝不清零**，否则策略丢失对球滚动趋势的估计；
- 摔倒三判据：根部相对球心过低 / 偏离球心过远 / 倾角超限；
- 场景：篮球直径约 0.24 m、质量约 0.62 kg，带 free joint 的自由刚体，真实接触，非固定支撑物。

## 3. PPO 与奖励
- **三尺度**：控制步 20 ms / episode 10–30 s / iteration = 一批数据一次梯度更新（smoke 64 环境×5–10 次；公开长训 4096 环境×500 次）；
- **PPO**：advantage = 实际回报 − critic 预期；clip 限制每次更新幅度——球上"一步改太狠就摔"，必须小步迭代；
- **privileged critic**：训练时 critic 额外读取球位置/线速度/角速度/接触信息，价值估计更准、梯度信号更干净；部署只导出 actor，不需摄像头或球检测器。**核心思想：训练信息可以比部署信息多——critic 只是教练，不上场**；
- **奖励七项的配比逻辑**：速度跟踪当主角（让"滚动"成为有目标的行为），球速只做小权重正则（防无指令乱滚）。若把球速当大权重惩罚，全局最优解退化成"僵硬站死不动"；动作变化惩罚 ↔ 评测指标 action-change RMS。你奖励什么，就得到什么。

## 4. ONNX / GPU / BPU 分工
- `checkpoint.pt → ONNX` 只固化 actor 纯函数（opset11）；critic、优化器、球状态全不进 ONNX；
- **Ubuntu 工作站**跑物理+渲染；**GPU（Torch CUDA）**仿真验证推理；**BPU（RDK X5）**板端 50 Hz 推理、不跑物理（真机上物理=真实世界，板子只管"读 IMU/编码器 → 组 obs → 推理 → 发关节目标"）；
- **先 GPU 后 BPU**：GPU parity 答"导出没导错"（PyTorch vs ONNX），BPU parity 答"编译量化后还对不对、时序预算够不够"；两层各管一段，不能反；
- BPU 默认关（`MICRODUCK_RUN_BPU=0`）是分步执行，不是可跳过；启用需板卡 + 工具链 + HBM 编译（ONNX/HBM 不进 Git）。
